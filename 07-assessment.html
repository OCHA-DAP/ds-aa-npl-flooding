7  Assessment

7.1 Summary of Findings

7.1.1 What GEOGloWS Provides

  • 86-year retrospective (1940–present) vs GloFAS’s 44-year record (1979–present). This is the single most valuable asset — nearly double the historical record for extreme value analysis.
  • 52-member ensemble forecasts with 15-day lead time, freely accessible via Python API with no authentication.
  • Pre-computed return periods (2–100 year) using Log-Pearson III distribution.
  • Built-in bias correction (SFDC/SABER method) that doesn’t require local observed discharge data.
  • Global reach-level resolution (~6.8 million river reaches) — much denser spatial coverage than GloFAS’s gridded output.

7.1.2 What GEOGloWS Cannot Provide

  • No reforecasts/hindcasts. The forecast archive extends only ~2 months. This is the critical gap — the AA framework needs reforecasts to calibrate trigger thresholds at specific lead times (3-day action, 7-day readiness). Without reforecasts, we cannot compute exceedance probability skill metrics or determine optimal ensemble agreement thresholds.
  • Spatial matching is fragile. The getriverid API is sensitive to coordinates — a 0.07° shift mapped to a completely different reach. For the Karnali, coordinate-based lookup failed entirely; we had to query the metadata table by upstream contributing area.

7.1.3 Return Period Discrepancies

GEOGloWS return periods are consistently higher than GloFAS:

Station GEOGloWS RP2 GloFAS RP2 Difference
Chatara (Koshi) 14,459 8,113 +78%
Chisapani (Karnali) 6,745 5,664 +19%

This reflects differences in model physics (RAPID vs LISFLOOD), record length (86 vs 44 years), distribution fitting (Log-Pearson III vs Gumbel), and potentially contributing area mismatches.

7.1.4 Event Detection

The event-level validation against DHM danger level crossings reveals whether GEOGloWS’s higher return period thresholds actually improve event detection relative to GloFAS’s known false alarm problem (33 false alarms at Chatara RP2, 95 at Chisapani RP2).

7.2 Recommendation

GEOGloWS should not replace GloFAS or Google GRRR for trigger calibration — the missing reforecasts make this impossible. However, it is worth incorporating as:

7.2.1 1. Validation Dataset

The 86-year retrospective provides a longer historical record for return period estimation and event catalog construction. Cross-referencing GEOGloWS events with GloFAS and DHM observations triangulates biases.

7.2.2 2. Complementary Real-Time Signal

Once triggers are calibrated using GloFAS/GRRR reforecasts, GEOGloWS’s 52-member ensemble forecast can serve as an independent confirmation signal. If both GloFAS and GEOGloWS forecasts exceed their respective thresholds, confidence in the trigger activation increases.

7.2.3 3. Bias Correction Benchmark

The SFDC method provides a globally-derived bias correction that doesn’t require local gauge data. Comparing SFDC-corrected GEOGloWS against GloFAS reanalysis can help quantify model biases.

7.3 Next Steps

  1. Investigate the Karnali spatial match further — the candidate reach (rid=441112306, area=40,149 km²) may not be the optimal match for Chisapani. Cross-checking with the HydroViewer visualization would help.

  2. Acquire a rating curve for Chatara and Chisapani — this would enable direct comparison between DHM water levels and model discharge, and unlock the correct_historical() bias correction method.

  3. Monitor GEOGloWS forecast archive — if the service begins retaining forecasts longer-term (or produces reforecasts), this changes the assessment fundamentally.

  4. Compare bias-corrected return periods against DHM thresholds — if SFDC correction brings GEOGloWS return periods closer to GloFAS values, it validates the correction approach.

  5. Evaluate the real-time forecast — track GEOGloWS ensemble forecasts during the upcoming monsoon season and compare against GloFAS forecasts and observed events.
